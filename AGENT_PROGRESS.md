## Decisions made

**Stack**
- **Astro 7 + TypeScript.** Repo was empty; static generation, near-zero JS,
  and a first-class image pipeline all fit a photography site.
- **No UI framework, no CSS framework.** The whole site ships hand-written CSS
  and ~4 kB of vanilla JS (nav, reveal, lightbox).

**Photographs live in `src/assets/`, not `public/`** — deliberate deviation
from the folder sketch in the brief. Astro can only generate AVIF/WebP
derivatives, srcset and intrinsic dimensions for images under `src/`. Files in
`public/` are copied untouched, which would have cost the performance
requirements in §34. The demo/real split the brief asked for is preserved as
sibling folders: `src/assets/demo/**` vs `src/assets/portfolio/**`.

**Demo images are generated, not downloaded.** The environment's network
policy blocks every stock-photo host (403 via the proxy on picsum, unsplash,
pexels), and the brief rules out hot-linking. `npm run demo:generate` produces
them locally, so there is no licence question at all. Full reasoning in
`docs/demo-assets.md`.

**Design**
- White background, `#101010` text, two greys. Colour only from photographs.
- No CSS filters over photographs — never auto-grayscale a colour photo.
- Inter (variable) + Instrument Serif for display. Both self-hosted; Google
  Fonts would add a third-party request and is unreachable at build time here.
- **Justified gallery rows**: flex-basis proportional to aspect ratio, so a row
  shares one height while every photo keeps its native ratio. No cropping.
- Every third landscape photo becomes a full-width anchor, for rhythm.
- One photo per row below 48rem — two portraits side by side at 360px are
  unusable.
- Dark lightbox; the rest of the site stays light.
- Mobile nav is a full white sheet, not a dropdown.

**Content**
- Czech throughout, including URL slugs (`/o-mne/`, `/cenik/`, `/portfolio/svatby/`).
- **No invented facts.** No fake biography, no fake prices, no fake phone
  number. Placeholders are visible and flagged in the UI where a visitor would
  otherwise be misled (draft notice on About, "Cena na vyžádání" on Pricing,
  placeholder contacts hidden from the footer).
- Contact page has **no form**, on purpose: a form on a static site means
  choosing a third-party provider and therefore where visitors' messages land.
  That is the client's decision. `mailto:` until they make it.

**Deployment**
- GitHub Pages, project site. `site` and `base` come from `SITE` / `BASE_PATH`
  env vars so moving to a custom domain is a one-line workflow change.
- All internal links go through `path()` in `src/lib/paths.ts`, so nothing
  breaks under a base path.

## Bugs found and fixed during QA

Recorded because each was invisible in code review and only showed up in a
real browser:

1. **Gallery collapsed to one photo per row.** `--row-h` was viewport-height
   based (58vh ≈ 610px), making every flex-basis wider than the container.
   Fixed with width-relative values.
2. **A photo alone on a row stretched to full width** — a 4:5 portrait became
   ~1500px tall. Capped portrait/square growth.
3. **The mobile menu could not be closed by touch.** The header's `z-index`
   created a stacking context, so the close button was painted *below* the
   full-screen sheet; only Escape worked, which a phone does not have. Header
   lifted above the sheet.
4. **The lightbox overflowed the screen for portrait photographs.** Two
   separate causes: `max-height: 100%` does not resolve against a grid row,
   and an absolutely positioned *replaced* element ignores its insets when
   width/height are auto. Fixed with padding + `object-fit: contain`.
5. **Two accessibility violations**: a 12px label using the decorative-only
   grey (2.6:1), and the location line in the mobile sheet sitting outside any
   landmark.
6. **`--c-ink-muted` was `#767676` — 4.54:1**, nominally over the 4.5:1 bar but
   rounding under once composited, so axe failed it on 13px text. Now
   `#6b6b6b` (5.3:1). Worth knowing: the first audit runs reported this page
   clean only because the scroll-reveal had not finished, so axe was skipping
   the elements as invisible. The harness now waits out the transition —
   an accessibility pass over animated content has to, or it checks nothing.

## Known issues

- Demo photographs are abstract tonal fields, not pictures of people. They test
  layout, ratios and tonality correctly, but they cannot tell us how the site
  feels with real portraits. Expect to retune gallery density after the swap.
- Martin Faltejsek's site URL was never given in the brief, and no reference
  site was reachable from this environment (see `docs/design-research.md`).
- A photo stranded alone on a gallery row (which happens when a full-width
  anchor photo forces a break) leaves roughly half a row of whitespace. It
  reads as deliberate asymmetry rather than a fault, so it is left as is —
  worth re-checking once real photographs are in.
- `dist/` is ~34 MB, of which ~4 MB is Astro emitting the original source
  images alongside the derivatives. They are **not referenced by any page**,
  so visitors never download them; it only inflates the Pages artifact.
- No Lighthouse run (the tool is not reachable from this environment); the
  numbers above come from `scripts/qa-perf.mjs` using the same
  PerformanceObserver metrics.
- A cold build generates ~570 image derivatives and takes ~3 minutes. The
  deploy workflow caches `node_modules/.astro` keyed on `src/assets/**`, so
  only runs that actually change photographs pay that cost.
